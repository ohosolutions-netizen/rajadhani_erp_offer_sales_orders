# Rajadhani Offer Sales Order

Sales Order version of the working Offer Invoice widget. The existing screen layout, customer and item search, barcode entry, packing quantities, percentage discounts, GST component rounding, delivery fields and review-before-save workflow are preserved.

## Deployment

Upload `dist/RajadhaniOfferSalesOrder.zip` through Sigma → extension → Configure → Upload Widget, then save/install the extension in your ERP organization. The widget opens as a modal from `salesorder.list.sidebar` and `salesorder.creation.sidebar` under **Rajadhani Offer Sales Order**. Turn Developer Mode off when using the installed ZIP.

Saving posts to `/erp/v3/salesorders`, reads `salesorder.salesorder_id` and `salesorder.salesorder_number`, refreshes Sales Orders and closes the popup. ERP assigns the order number. The widget does not call invoice creation, email, confirmation or approval endpoints. After success the screen locks; an ambiguous failure blocks retry until the operator checks the Sales Order list.

The existing `erp_admin` connection name and India API base are retained. The manifest requests `ERP.salesorders.ALL` in place of invoice access. **Authorize Sales Order access in the actual Zoho connection and reauthorize it for each user**; changing manifest text does not grant permissions. The documented create scope is `ERP.salesorders.CREATE`; reading existing orders needs `ERP.salesorders.READ`. Retained customer/item scopes and connection metadata come from the working copy. Use the connection JSON generated by your tenant if its configuration differs. Customer, item, tax, location and salesperson lookups still need their existing permissions.

Custom field IDs in `app/config.json` are blank in the supplied copy. Map them to **Sales Order custom fields**, not invoice custom fields, to persist those values. Existing behavior is retained: unmapped values are labelled “Not sent to ERP yet” and omitted from the payload. Organization ID is obtained from the SDK.

`salesOrderQuantityMode: "pieces"` retains the working quantity semantics: order quantity × pieces per pack is sent as quantity, with the per-piece rate. `order` instead sends order quantity and the equivalent pack rate. M Unit and Ratio continue to come from item master fields. Item discounts are percentages applied before tax; CGST and SGST are rounded separately for each line, followed by final rupee rounding.

The existing Sales Order selector remains in the same position. As in the supplied copy, import is available in preview only; live import remains disabled pending confirmation of source quantity units. Source order line IDs are never sent when creating a new Sales Order.

## Build and checks

- `npm ci`
- `npm run build` — standalone preview, ZET validation and ZIP packaging.
- `npm test` — calculation/payload tests and Playwright browser flows.
- `npm run preview` — open `/dist/SalesOrderPreview.html` on port 5179.
- `npm run zet:run` — local Zoho Developer Mode server.

`dist/SalesOrderPreview.html` is an offline preview with fictional records and saving disabled. The deployable ZIP contains only `app/` and `plugin-manifest.json`. The separate original `Rajadhani ERP Edit invoice/` widget and obsolete invoice artifacts are kept locally, ignored by this repository and excluded from the package.

Local tests use mocked ERP responses. Installation, connection authorization, custom fields and final totals need verification in your Zoho organization.
